### 心体の健康

- 心体で最も気を付けないといけないのは睡眠と休息
    - まず睡眠に関してはApple Watchの睡眠トラッキングが睡眠の質を計測する唯一の方法
        - 睡眠スコアを90以上に持っていけたら体調は担保できる
        - 逆に体調が悪いと集中力、メンタル全てが悪くなってしまう、特に英語には大きな影響を与えてしまう
        - 90以上にするにはおそらく寝る前にリラックスして、何もしない時間が1時間ぐらい必要、そうしないとInterruptionsが多くなってしまう
    - 休息については半日何も考えないというのが簡単ではないが、これをしないとホワイトスペースが生まれず新しいアイデアを思い付けない
        - 時間は午前中の2-3時間ぐらいで良い
    - これらをしないと睡眠と休息のアクションと質が担保されない
- 食事、運動、美容はアクション実行にコミットする
- 夜以外はリラックスしすぎないこと、これは理性で抑える、ルーティンを崩してはいけない
- 平日の朝はボランティアがない日はジムに行く、雨の日はコンドのジムを使う

### 素晴らしい人間性

- 前提として、Intentional Unbalanceをかけるなら、このセクションは優先度が低く、リソースを割きすぎなくて良い
    - 理由は他のセクションの重要度およびアクション強度が高いため
    - 全てを均等にするのは厳しいため意図的にUnbalanceにする
    - その中でも一応、戦略を以下に示す
- 人間性というのは自分がきつい状況に行くほど、目指すべきものを発揮するのが簡単ではなくなる
    - 実は「高負荷な作業」をしている人ほど、「性格が悪くなる形」で破綻していく
    - これはその人の性格に問題があるだけ、とは言えない
    - ストレスがかかると前頭前野(意図的・価値ベースの判断を司る)の働きが下がり、習慣や反射を司る回路に主導権が移るためである
- 回復設計
    - トップアスリートやエグゼクティブ、つまり「負荷を下げるという選択肢がない人たち」で、彼らの結論は「高負荷者ほど回復を意図的に・リズミカルに入れないと、パフォーマンスより先に人格が壊れる」だった
- 社会的接触
    - 社会的接触が減ると脳が自己防衛モードに傾き、他者への警戒が上がり、会話の解釈がネガティブに偏ることが示されている
    - つまり一人作業が続くと「性格が内向きになる」のではなく、社会認知そのものが一時的に劣化する
    - 会う人は固定化するのではなく、一定のランダム性を持たせた方が効果的
        - ミートアップへの参加を検討する
- If - thenルールで検知・修正する
    - 「もし自分がXな態度を取っていたら、Yのアクションをする」という風にif文を設計する
    - ポイントは、ifを「感情や状況の兆候」レベルまで具体化すること
    - 自分にとってのif - thenルールは以下
        - もし同僚に対して、強い口調や雑なコミュニケーションを取っていたら
            - 一旦、頭を冷静にして、落ち着いた口調でコミュニケーションを取る
        - もし相手のメッセージに対して、返信が遅くなったり、雑なコミュニケーションを取っていたら
            - 「返信遅くてごめん」と謝ったり、自分から予定や話題を提案したりする
        - もしプライベートの相手とのコミュニケーションで、自分が機嫌が悪くなっていたり、相手の話に興味の無いそぶりを出していたら
            - 深呼吸して、「仕事モード」ではなく、「遊びモード」でその場の人生を楽しむ
                - 仕事を遊びに持ち込まない
    - Contextとそれに対する反応を反復することでそれが18〜254日の幅の中で習慣化される
- 人間性の検知ループ
    - 朝：予測
        1. Wish: 今日、人間性の面で何を実現したいか1つだけ選ぶ(例:「夕方の友達との通話で相手First」)
        2. Outcome: それができた時の感覚を10秒想像する
        3. Obstacle: 今日それを邪魔しそうな内的障害を予測する(ここが核心。「午後にコードレビューが荒れたら、通話の時間が惜しく感じるだろう」)
        4. Plan: その障害に対するif-thenを確認する
    - 夜：崩れた日だけポストモーテム
        - 書くのは崩れた日だけで良く、5分以内
        - 何が起きたか(事実のみ):「友達からの電話を早く切り上げた。相手の近況をほぼ聞かなかった」
        - トリガーは何か:「その直前、SRモデルの学習が失敗して3時間溶かした後だった」
        - どのif-thenが発火しなかったか / そもそもifが未定義だったか:「『作業で失敗した直後の会話』というifを想定していなかった」
        - 修正:「if『大きな失敗の直後に人と話す』then『最初に「今日ちょっと失敗してテンション低いかも」と宣言する』を追加」
    - 週末：週に一回のログ集計
        - 週末に1回、ログを見返してトリガーの頻度集計
        - 数週間分たまると「崩れの8割は『学習/実装の失敗直後』と『睡眠6時間未満の日』に起きている」のようなパターンが必ず見えてくる
